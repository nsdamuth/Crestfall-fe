## 1. Package: unified modal frame (`modal-frame`)

Blueprint 2.5 built as a kit package. The behavioral half of this
frame already exists and is ruled: `components/ui/ModalShell.jsx`
(LOOM-separated 7 Aug 2026, contract v1.0.0) owns the veil, the
backdrop-dismiss guard, Escape, and the body scroll lock, and eleven
callers depend on it unchanged. What does NOT exist anywhere is the
ruled PANEL: every caller today hand-rolls its own surface, border,
radius, shadow, and close control through `panelClassName`. The kit
frame is that panel, standardized once, composed on top of ModalShell
behavior.

### 1.1 Files (LOOM shape, FRONTEND-SOP section 1)

- `components/kit/KitModalFrame.jsx` (binding shell)
- `components/kit/modal-frame/KitModalFrame.view.jsx`
- `components/kit/modal-frame/useKitModalFrameViewModel.js`
- `components/kit/modal-frame/KitModalFrame.contract.js`
- `components/kit/modal-frame/KitModalFrame.fixtures.js`
- `components/kit/modal-frame/README.md`
- `app/dev/ui-preview/modal-frame/page.jsx` plus its

  is `/dev/ui-preview/modal-frame` exactly as the gate manifest names
  it (not `kit-modal-frame`; the manifest's address wins over the

### 1.2 Contract, prop by prop

Line 1 of `KitModalFrame.contract.js`:

```js
export const KIT_MODAL_FRAME_VIEW_CONTRACT_VERSION = "1.0.0";
```

Version format is semver, matching the kit family (T14 is open; family
practice governs).

| Prop | Type | Default | Meaning |
|---|---|---|---|
| `children` | ReactNode | `null` | Panel content. The caller owns content padding and internal layout; the frame adds no content padding of its own (the `.cf-modal-frame` recipe's own comment: content goes inside unchanged). |
| `onClose` | `(() => void) or null` | `null` | Fired by ALL THREE ruled dismissal paths: backdrop click, Escape, and the close control. Null-safe: with no handler all three are no-ops (matching ModalShell's no-close fixture). |
| `closeOnBackdrop` | boolean | `true` | Pass-through to ModalShell behavior. The ruled default is on; turning it off is a caller escape hatch that no Sprint A consumer uses. |
| `closeOnEscape` | boolean | `true` | Same as above, for Escape. |
| `variant` | `"modal"` or `"sheet"` | `"modal"` | `"modal"` is the ruled responsive frame: bottom-docked sheet under 700px, centered floating surface at 700px and up. `"sheet"` is bottom-docked at every width; it exists solely so sheet-only consumers that gate their own mounting by viewport (the dropdown under 700px, Phase 4) inherit the one frame per Ruling 1 instead of hand-rolling a second sheet. No other value, no fourth surface. |
| `panelClassName` | string | `""` | Per-surface WIDTH and HEIGHT caps only (blueprint 2.5: width and height stay per-surface, not unified), for example `max-w-lg` or `min-[700px]:w-fit`. Never surface, border, radius, shadow, or dismissal overrides; a caller needing those is out of contract. |
| `ariaLabelledBy` | string, optional | none | Forwarded to the dialog, same as ModalShell. |
| `ariaDescribedBy` | string, optional | none | Forwarded to the dialog. |
| `ariaLabel` | string, optional | none | Fallback accessible name for surfaces with no heading id (the dropdown sheet passes its group label). Rendered as `aria-label` on the dialog only when `ariaLabelledBy` is absent. |

There is no `isOpen` prop: the frame renders when mounted, exactly the
ModalShell convention every current caller already follows
(`{open && <ModalShell .../>}`). There is no prop to hide the close
control: the circular close control is fixed frame anatomy per 2.5.

### 1.3 Rendered anatomy, exact

- **Composition.** `useKitModalFrameViewModel` composes
  `useModalShellViewModel` (escape, scroll lock, backdrop guard) and
  returns merged view props; `KitModalFrame.view.jsx` renders
  `ModalShellView` with the frame's alignment classes and the standard
  panel inside it. ModalShell's contract v1.0.0 is untouched.
- **Portal.** The shell portals its subtree to `document.body`
  (`createPortal`, guarded `typeof document !== "undefined"`), for the
  same reason the dropdown sheet already does: a `backdrop-filter`
  ancestor (the sticky filter bar, the frosted top bar) becomes the
  containing block for `fixed` descendants, so a frame opened from
  chrome must escape it. Page-level consumers render identically with
  or without the portal.
- **Overlay** (from ModalShellView): `fixed inset-0 z-50`, veil
  `bg-[var(--scrim-strong)]` with
  `backdrop-blur-[var(--blur-panel)]`. Alignment via `className`:
  variant `modal` gets
  `items-end p-0 min-[700px]:items-center min-[700px]:p-[var(--space-4)]`;
  variant `sheet` gets `items-end p-0` at every width.
- **Panel base classes** (before `panelClassName` is appended):
  `relative w-full max-h-[92dvh] overflow-y-auto bg-[var(--surface-4)]
  border border-[var(--line)] shadow-[var(--shadow-modal)]`.
  Variant `modal` adds
  `rounded-t-[var(--radius-lg)] rounded-b-none border-b-0
  pb-[env(safe-area-inset-bottom)] min-[700px]:rounded-[var(--radius-lg)]
  min-[700px]:border-b min-[700px]:pb-0`; variant `sheet` adds
  `rounded-t-[var(--radius-lg)] rounded-b-none border-b-0
  pb-[env(safe-area-inset-bottom)]` with no 700px overrides. LARGE
  corners everywhere, top corners only while docked, matching the
  ruled `.cf-modal-frame` recipe in app/design-system.css.
- **Close control**: rendered by the frame inside the panel,
  `absolute right-[var(--space-3)] top-[var(--space-3)]`, circular:
  `flex h-[var(--control-md)] w-[var(--control-md)] items-center
  justify-center rounded-[var(--radius-full)] border
  border-[var(--line-whisper)] bg-[var(--surface-2)]
  text-[var(--ink-dim)]`, lucide `X` size 18, `aria-label="Close"`,
  `kit-focus`, hover `text-[var(--ink)]`, active
  `bg-[var(--state-pressed-fill)]`, disabled n/a (it never disables).
  Five states per 2.0; this is the exact recipe the image overlay's X
  and the dropdown sheet's X already use, now owned in one place.
  Content that must not sit under it clears it with its own top or
  right padding (per-surface concern).
- **Dismissal**: backdrop `mousedown` closes only when
  `event.target === event.currentTarget` (press-and-drag from inside
  the panel never false-closes); Escape closes; the close control
  closes. All inherited from the ModalShell ViewModel, all three
  ruled 10 Aug 2026 (blueprint 2.5 enforcement note).
- **Scroll lock**: body `overflow: hidden` while mounted, previous
  value restored on unmount (LIFO-safe for the ruled
  stacked-picker-over-modal case; each layer keeps its own lock).
- **Focus trap**: none exists in ModalShell today and none is
  invented here; logged as a known gap in the README, consistent with
  current behavior.

## 5. Unification: dropdown sheet and popover onto the frame

Ruling 1 ("one frame for modal, picker, sheet") applied to the one
place in the kit that still hand-rolls a sheet: `KitDropdown`'s
under-700px panel. The ruled dropdown behavior is explicitly
UNCHANGED; this is a chassis swap under it.

### 5.1 Behavior that must read identically before and after

- Trigger grammar: category label, gold value (single-select) or gold
  count (multi-select), chevron; marked treatment when open or when
  any selection exists.
- Open/closed is presentation-only local state in the view.
- Outside click closes; Escape closes; single-select closes on pick;
  multi-select stays open for further toggles.
- Selected rows: gold text, leading check; counts trailing; disabled
  rows read the word "Soon"; empty panel reads "No options".
- 700px and up: popover below the trigger, `--surface-4`, 1px
  `--line`, `--radius-md`, `--shadow-popover`, min 13rem, max 19rem
  scrolling, NO veil, NO scroll lock (popovers are not modal).
- Under 700px: bottom-docked sheet, `--scrim-strong` veil with
  `--blur-panel`, LARGE top corners, `--shadow-modal`, safe-area
  bottom padding, label header, circular close control, rows bump to
  `--control-md` at coarse pointers.

### 5.2 The path

- The view replaces its CSS-only split (`hidden min-[700px]:block` /
  `min-[700px]:hidden`) with a `matchMedia("(max-width: 699.98px)")`
  presentation-only flag (same sanctioned local-state class as the
  open flag; listener added and removed in the existing dismissal
  effect's manner). While open: phone width mounts the frame sheet;
  700px and up renders the existing popover, byte-for-byte unchanged.
- The sheet becomes `KitModalFrame` variant `"sheet"`,
  `onClose={() => setIsOpen(false)}`, `ariaLabel` set to the group
  label, containing the existing label header row (its own X button
  DELETED, the frame's close control replaces it; the header row
  gains `pr-[calc(var(--control-md)+var(--space-3))]` so the label
  never sits under the close control) and the existing `PanelRows`
  listbox, unchanged.
- The dropdown's own portal wrapper for the sheet is deleted; the
  frame portals itself (1.3). The dropdown's outside-pointerdown
  listener keeps guarding the popover; while the sheet is up, the
  frame's backdrop guard does that job (the sheet subtree no longer
  needs the `sheetRef` containment check once the frame owns the
  backdrop; the ref plumbing is removed with it). The dropdown's own
  Escape listener stays for the popover; while the sheet is open the
  frame also answers Escape, and both call the same idempotent close.
- Inherited-by-construction change, deliberate: the phone sheet now
  scroll-locks the body while open (frame law); it previously did
  not. The popover still never locks. Recorded here so the diff is
  not mistaken for drift.

### 5.3 Contract

`KIT_DROPDOWN_VIEW_CONTRACT_VERSION` stays `"1.0.0"`: no prop is
