GAPS, SESSION 3 (image viewer and brush editor, notes 6 and 6a, 10 Sep 2026)
8. Edit run (brush plus crop). Screen: the brush editor inside the image viewer (components/kit/image-editor, opened by Edit on the viewer's bottom bar): painted areas, a crop box, and a prompt, submitted by one Generate button. Call: none yet; the FE wants POST /api/studio/image-generation/jobs with mode "EDIT", { sourceImageOutputId, maskPng (a PNG data URL at the source image's native size, white where painted, black elsewhere), crop: { x, y, width, height } in source pixels or null, prompt }. Response: the same job shape, whose output is a NEW image output carrying parentImageOutputId and derivation "EDIT", never an overwrite of the source (RULED 10 Sep 2026). Cost: 20 coins flat per run (EDIT_RUN_COIN_COST, components/studio/image-studio/image-studio-workbench/useImageStudioWorkbenchViewModel.js, until gap 2 serves prices). Unverified: whether the mask should travel as a data URL or an upload, and whether the crop applies before or after inpainting. Until it lands, Generate in the editor renders disabled with the Soon chip and "Not available yet".
9. Upscale. Screen: the Upscale button beside the image's current pixel size in the viewer header (the only place it exists). Call: none yet; the FE wants POST /api/studio/image-generation/outputs/{id}/upscale with no body. Response: a NEW image output (parentImageOutputId, derivation "UPSCALE") with real width and height; the produced size is the server's and the FE never states a factor. The download menu's Extra Large row and the crop box's larger sizes unlock from that response. Cost: 10 coins (UPSCALE_COIN_COST, same file, until gap 2). Unverified: the model, the size cap, and whether the original stays downloadable. Until it lands, Upscale renders disabled with the Soon chip and "Not available yet", and Extra Large stays grey.
10. Output dimensions and variant sizes. Screen: the pixel size line under the viewer title, the Large download row's size note, and the crop pixel entry's clamp. Call: the existing history feed, GET /api/studio/image-generation/jobs (fetchImageGenerationHistory). Today width and height on an output are often null (getMediaHistoryStoredDimensions hunts six paths and the FE falls back to measuring the loaded image in the browser). Proposed: every output carries width and height, plus the pixel size of each stored variant (thumbnail, card, display, original) so the download menu can show real numbers on Small and Medium instead of none. Cost: n/a.
11. Assign an image that has no asset. Screen: Assign on the viewer's bottom bar. Call: today reassignImageOutput POST /api/media/images/{id}/reassign requires sourceCreationId (the asset the image already sits on), so an image with no asset cannot be assigned and the FE renders Assign disabled with the Soon chip. Proposed: accept a request with destinationCreationId only (no source) or add POST /api/media/images/{id}/assign. Cost: the reassign call charges 1 coin today (the FE shows the server's coinCost from fetchImageReassignmentContext); state the cost for a first assignment.
12. Linked library items. Screen: the library grid and the viewer after an edit run or an upscale. Call: the history feed (gap 10). Proposed: derived outputs (gaps 8 and 9) come back as their own library items with parentImageOutputId and derivation, in the same feed, so the grid shows them beside the source and the viewer can later read "Edited from" or "Upscaled from". Cost: n/a.
