WHAT THE BRANCH HOLDS
- Branch fe/media-studio in Crestfall-fe, off staging. Latest code commit 3c7a95a5 (10 Sep 2026); this handoff lands on top of it as a docs-only commit.
- The Media Studio page at /studio/v2/images: one composer with three modes. Generate runs the live image job. Remix takes up to six characters plus one location with @ mentions in the prompt. Video takes Text to video (the five asset tiles) or Image to video (one library image), a Custom director with one prompt row per 5 seconds, aspect ratio, duration, and quality.
- One shared asset picker and one custom preset modal serve every slot in every mode; the picker also serves camera framing and the Video source image.
- The image viewer with zoom and pan, a download size menu, Assign, and Share, and inside it the brush editor (paint, erase, crop with a pixel entry, a prompt) with Upscale beside the image's pixel size.
- Every backend-bound action the Chassis cannot run today ships as Soon: the control is disabled, shows the coin glyph and the cost, carries the Soon chip, and reads "Not available yet" on hover. Generate on Remix, Generate on Video, the editor's Generate, Upscale, Assign without a source, and the counts above four are all in that state.

WHAT THE BACKEND DOES TODAY
- One job type, create_image: 1 to 4 images per run, fixed sizes up to 1040px on the long edge, a flat 5 coins per job, seed control, six singular ingredient slots, reference images accepted and stored but read by no provider.
- Verified in crestfall-main on 10 Sep 2026: createImageGenerationJob.js returns 501 VIDEO_GENERATION_NOT_AVAILABLE on a video mode and rejects every operation but create_image; there is no upscale, inpaint, mask, crop, segmentation, remix, or video job; all three providers declare imageEdit, upscale, and video false; the VIDEO_GENERATION capability defaults to deny and nothing enforces it; imageCostPolicy.js is one flat constant whose estimator takes no arguments.

GAPS
One line per gap, in the shape: what the FE calls, the inputs, the response the FE expects, what is unverified. Numbers never change; a superseded gap keeps its number and points forward.

Inputs: settings.outputCount up to 128 (the Generate list is 2 to 128, the Remix list 1 to 128; the rows above 4 render disabled with the Soon chip). Response: the same job shape with one output per image. Unverified: whether one job can queue more than four outputs on the provider; the frontend constant IMAGE_COUNT_BACKEND_MAX (components/studio/image-studio/imageStudioData.js) moves the day it lands.
2. Served prices. Call: none yet; proposed GET /api/studio/image-generation/pricing. Inputs: none. Unverified: whether prices are per image or per job (gap 14); until it exists the frontend reads its constants and this file says so.

7. Preset save. 8. Edit run (brush plus crop). Call: none yet; the FE wants POST /api/studio/image-generation/jobs with mode "EDIT". Inputs: { sourceImageOutputId, maskPng (a PNG data URL at the source image's native size, white where painted, black elsewhere), crop: { x, y, width, height } in source pixels or null, prompt }. Response: the same job shape whose output is a NEW image output carrying parentImageOutputId and derivation "EDIT", never an overwrite (RULED 10 Sep 2026). Unverified: whether the mask travels as a data URL or an upload, and whether the crop applies before or after inpainting.
9. Upscale. Call: none yet; the FE wants POST /api/studio/image-generation/outputs/{id}/upscale with no body. Inputs: the output id. Response: a NEW image output (parentImageOutputId, derivation "UPSCALE") with real width and height; the produced size is the server's and the frontend never states a factor; the download menu's Extra Large row and the crop box's larger sizes unlock from it. Unverified: the model, the size cap, and whether the original stays downloadable.
10. Output dimensions and variant sizes. Call: GET /api/studio/image-generation/jobs (fetchImageGenerationHistory), the existing feed. Inputs: none. Response: width and height on every output plus the pixel size of each stored variant (thumbnail, card, display, original), so the viewer's size line and the download menu show real numbers. Unverified: nothing; today width and height are often null (getMediaHistoryStoredDimensions hunts six paths) and the frontend measures the loaded image in the browser.
11. Assign an image that has no asset. Call: reassignImageOutput POST /api/media/images/{id}/reassign, which today requires sourceCreationId. Inputs: proposed destinationCreationId only, or a new POST /api/media/images/{id}/assign. Response: the reassigned image and its coinCost (the frontend shows the server's number from fetchImageReassignmentContext). Unverified: the cost of a first assignment; the reassign charges 1 coin today. Until it lands, Assign on an image with no asset renders Soon.
12. Linked library items. Call: the history feed (gap 10). Inputs: none. Response: derived outputs (gaps 8 and 9) as their own items in the same feed with parentImageOutputId and derivation, so the grid shows them beside the source and the viewer can read "Edited from" or "Upscaled from". Unverified: nothing.
13. Remix job (supersedes 4). Call: none yet; the FE wants POST /api/studio/image-generation/jobs with operation "remix_image". Inputs: { remix: { characters: [1 to 6 ingredient unions in slot order, each { mode: "asset", assetId } or { mode: "custom", text }], location: an ingredient union or { mode: "none" } }, prompt: { userPrompt with the @img1 to @img6 and @location mentions as typed, negativePrompt }, settings: { outputCount, aspectRatio } as today }; @imgN resolves server-side to characters[N - 1] and @location to the location. Response: the same job shape. Unverified: whether the experimental multi-reference ComfyUI pack under data/base/new/V2.1 (six-reference cap, identity-blending warning in its README) is the intended engine; whether a custom-text character counts as a reference or as prompt only; whether the location contributes its image or its prompt only. Verified: createImageGenerationJob.js holds six SINGULAR slots and throws IMAGE_GENERATION_MULTIPLE_VISUAL_SUBJECTS_NOT_SUPPORTED when character and playerCharacter are both set, referenceInputs[] is stored and read by no provider, and no mention resolver exists.
14. Cost rule, per image or per job. Call: the job POST (every job). Inputs: settings.outputCount. Response wanted: a ruling, not an endpoint. Finding: imageCostPolicy.js charges IMAGE_GENERATION_BASE_COIN_COST = 5 as one flat charge per job and ignores outputCount, while the frontend displays and gates on count times the cost for Generate, Remix, and Video. Unverified: the intended rule; the frontend follows it from one constant either way, no change needed on its side.
15. Video job (supersedes 5). Call: none yet; the FE wants POST /api/studio/video-generation/jobs. Inputs: { mode: "TEXT" | "IMAGE", ingredients: the five slot unions as the image job takes them (TEXT only), sourceImageOutputId (IMAGE only), prompt: { userPrompt } (optional on TEXT, required on IMAGE), settings: { aspectRatio (the image job's five values), outputCount (1, 2, 4, 8, 16, 32), durationSeconds (5 to 30 in steps of 5), quality: "720p" | "1080p" }, director: [{ fromSecond, toSecond, prompt }] (empty when the director is closed) }. Unverified: the engine (no video provider exists to check against); whether a Text to video job takes the five ingredients or only a character; whether the source image drives identity or only the first frame; whether the director rows run as one job or a chain of segments; the real count cap; whether the five aspect values map to served dimensions; whether gap 14 applies to videos the same way. Verified: the 501 guard, every provider declaring video false, the deny-by-default capability nothing enforces, the argument-less cost policy, and no video route, service directory, migration, or vendor client anywhere in crestfall-main.
