WHAT THE BRANCH HOLDS
- Branch fe/global-search in Crestfall-fe, off staging. The search is built into the real top bar on every studio page; there is no preview route.
- One Kit package, components/kit/global-search (KitGlobalSearch), and one top bar adapter, components/studio/studio-top-bar/useGlobalSearchAdapter.js. The adapter is the only file that fetches.
- Data approach, RULED 10 Sep 2026: fetch once on the panel's first open, filter in the browser. On first open the adapter calls, in parallel, GET /api/creations?view=summary, GET /api/studio/story-rooms, GET /api/studio/image-generation/jobs?limit=60, GET /api/community/creations, and GET /api/community/creators, holds the lists for the session, and refreshes on the next open after five minutes. Typing filters in memory: every typed term must appear in the item's title, subtitle, description, tags, or handle.
- Scope words "my" and "community" keep one section; typed prefixes (character:, player:, pose:, outfit:, location:, preset:, story:, adventure:, creator:, lore:, media:) keep one type. Both are frontend grammar over the same lists.
- Destinations, every one a route that exists: owned creations open /studio/v2/editor/[id] (timelines /studio/v2/lore/timelines/[id]), stories in progress open /studio/v2/stories/[id], community creations open /studio/creations/[id], creators open /studio/v2/creators/[handle]. Generated media rows render Soon because no page opens with one output selected (a frontend follow-up, NOTES.md).

WHAT THE BACKEND DOES TODAY
- Verified in crestfall-main on 10 Sep 2026: no search route exists. services/api/src/server.js dispatches no /v1/search; no list route accepts q, search, or query; the repo holds no ILIKE, to_tsvector, tsquery, or pg_trgm; every creation read goes through PostGraphile JSON RPCs (listOwnedCreationsJsonAsActor, listOwnedCreationSummariesJsonAsActor, listPublicCreationsJsonAsActor, listPublicProfilesJsonAsActor) whose arguments are type, status, content rating, and owner ids only.
- GET /v1/studio/creations (creationsRoute.js) takes type, status, view=summary; own only; no paging; returns every owned creation.
- GET /v1/community/creations (communityRoute.js) takes type and content_rating; public only; no paging; returns every public creation (communityService.js post-filters in JS).
- GET /v1/community/creators takes nothing; the Next proxy app/api/community/creators/route.js drops the query string entirely; no paging; two queries per profile.
- GET /v1/studio/story-rooms takes nothing; own only; no paging; sorted by last activity.
- GET /v1/studio/image-generation/jobs takes limit (1 to 60, default 30) and cursor; own only; prompt text sits inside job.promptSnapshot; width and height often null (MEDIA-STUDIO-BACKEND.md gap 10).
- GET /v1/lore/publications takes limit and offset but is not proxied in Crestfall-fe (only app/api/lore/[id]); community lore reaches the search through /v1/community/creations?type=LORE.
- A vector stack exists for chat memory only (engine-middleware retrieval broker, runpod embeddings) and is not wired to creations, profiles, or media.

GAPS
One line per gap, in the shape: what the FE calls, the inputs, the response the FE expects, what is unverified. Numbers never change; a superseded gap keeps its number and points forward.

1. Global search route. Call: none yet; the FE wants GET /api/search proxied to GET /v1/search. Inputs: q (free text), scope ("my" | "community", default both), type (one of CHARACTER, PLAYER_CHARACTER, POSE, OUTFIT, LOCATION, IMAGE_PRESET, ROOM_TEMPLATE, STORYLINE, LORE, TIMELINE, CREATOR, MEDIA, or absent for all), limit (default 20 per section), cursor. Response: { own: { results, pageInfo }, community: { results, pageInfo } } with each result { id, type, title, subtitle, imageUrl, ownerHandle, visibility, updatedAt } and pageInfo { hasNextPage, endCursor }; the FE keeps building the href from id and type as it does today. Unverified: the matching engine (ILIKE on title and description versus a full-text index), whether Internal visibility rows are excluded from community results (the product model says Internal is unsearchable), and ranking. The day this lands the adapter's fetch-once path becomes fetch-per-query and every gap below closes for the search.
2. Community creations list, query and paging. Call: GET /api/community/creations (fetchCommunityCreations). Inputs: proposed q, limit, cursor beside today's type and content_rating. Response: today's creation summary shape plus pageInfo. Unverified: nothing; today the route returns every public creation and the FE downloads the whole catalog on first open, the same download the Community page makes.
