# Design rulings inventory, 11 Sep 2026

Read-only inventory against the 92 Current routes ruled in `docs/reviews/ROUTE-STATUS-2026-09-11.md`, checked against the six rulings in `docs/decisions/2026-09-11-design-rulings.md`. No product code was edited to produce this document.

## Method

Run as a dynamic workflow of 22 read-only agents in one fan-out: 11 batches swept the eyebrow ornament / sharp-line pattern (R6), 1 base agent plus 7 batches surveyed every modal component (R8, R9), and 3 batches surveyed every native `<select>` element (R10). Every batch was given the full 92-route-to-page-file map and told to ground each finding in a Current route by direct page-file match or a one-hop importer trace, or to say plainly when no Current route grounds a file.

Sweep target for part (a): every file using `var(--grad-rule)` inline (the sharp-line gradient, `linear-gradient(90deg, gold, transparent)`, fading on one side only) plus every file importing the shared `components/ui/eyebrow/Eyebrow.view.jsx` component with its rule mark enabled. 92 candidate files, 234 live usages found across 91 of them. The 92nd file, `components/studio/creations/creation-preview-modal/CreationPreviewModal.view.jsx`, was checked directly: both its `<Eyebrow>` call sites (lines 267 and 355) pass `showRuleMark={false}`, so no rule graphic renders there and it correctly contributes zero rows.

Sweep target for part (b)/(d): all 58 canonical modal components (binding-shell wrapper files deduplicated against their `.view.jsx` counterpart), plus the 5 shared base components (`KitModalFrame`, `ModalShell` x2, `CrestfallOptionModal`, `KitPickerModal`) read first for context.

Sweep target for part (c): all 47 native `<select>` occurrences in live product code (excluding comments and the retired `/dev/ui-preview` harness, which is not among the 92 Current routes).

## a. Eyebrow ornament / sharp line inventory (R6)

**234 live usages found** across 91 of 92 candidate files. **3 keep** under R6 (the primary page eyebrow above that route's own page title). **231 are removals** under R6 (section headers, cards, modals, forms, and sidebars).

## b. Modal dimension inventory (R8) and header/divider inventory (R9)

### Shared modal base components

Five files form a two-tier shared modal system that is NOT applied consistently, which is exactly the kind of gap a rulings inventory should flag.  Tier 0 (positioning primitive): components/ui/modal-shell/ModalShell.view.jsx is a bare veil + role="dialog" wrapper with zero built-in width, height, divider, or header/eyebrow chrome -- it renders only what panelClassName/panelStyle/children hand it.  Tier 1 (frame): components/kit/KitModalFrame.jsx (thin binding shell) wires components/kit/modal-frame/useKitModalFrameViewModel.js (owns the three variant recipes -- modal/sheet/viewer -- for width via a --panel-width custom property + panelWidth prop, height via max-h-[92dvh]/[100dvh], and veil) together with components/kit/modal-frame/KitModalFrame.view.jsx (owns chrome: the circular close button in its two placements, the shared FadeDivider primitive built on --line-fade -- a rule that fades to transparent at BOTH ends, confirmed at docs/DESIGN-TOKENS.md:483, unlike a one-sided fade -- and the optional sheet grabber/unsaved-changes confirm interstitial). Portals to document.body via createPortal. Critically, KitModalFrame itself renders NO title, eyebrow, or header/body divider for the 'modal' and 'viewer' variants -- that is entirely left to each caller's children.  Tier 2 (real modal bodies) diverge from each other in exactly what the frame leaves open: components/studio/create/npc-registry/modal-shell/ModalShell.view.jsx renders a static "NPC Registry" gold eyebrow above a dynamic h2 title, then its own inline --line-fade divider before the scrollable body, capped to max-w-4xl (56rem) with no panelWidth override. components/kit/picker-modal/KitPickerModal.view.jsx renders only a bare h2 (no eyebrow) and puts its own inline --line-fade divider between the body and the FOOTER rather than between header and body, narrows the frame via panelWidth="42rem", and layers an inner max-h-[85vh] (vh, not dvh) cap on top of the frame's own max-h-[92dvh]. components/ui/crestfall-option-modal/CrestfallOptionModal.view.jsx is the outlier: it bypasses ModalShellView/KitModalFrame entirely, hand-rolling its own fixed inset-0 overlay with the same visual vocabulary (max-w-4xl, mobile bottom-sheet/desktop-centered pattern, border-b-0 -> border-b at 700px) but with NO divider at all between its header and body (a plain margin-top gap instead) and a content-sized/auto-height panel instead of any max-h-[92dvh] cap; its gold-eyebrow style is used only for the closed trigger label and a "custom" sub-panel, never for the open modal's own header.  Net: three different divider placements/behaviors (header-to-body via shared token, body-to-footer via shared token, none at all via hand-rolled overlay), three different width mechanisms (shared --panel-width variable, that variable further capped by a legacy max-w-* class, and an independent hand-rolled max-w-4xl with no shared variable), and eyebrow support present in exactly one of the four real modal headers (NPC Registry) despite the same --gold-ornament eyebrow style existing in every file's vocabulary.

**`components/kit/modal-frame/KitModalFrame.view.jsx`**

- Width: This view renders no width class itself: `panelClassName` is forwarded verbatim to ModalShellView (`className={panelClassName}` at KitModalFrame.view.jsx:169). Callers override the modal width via a `panelWidth` prop (e.g. "42rem", "56rem") which becomes an inline `{'--panel-width': panelWidth.trim()}` style (useKitModalFrameViewModel.js:160-163), rendered at KitModalFrame.view.jsx:170 as `panelStyle={panelStyle}`. Per docs/DESIGN-TOKENS.md:483, `--line-fade` = `linear-gradient(90deg,transparent,rgba(242,209,148,.13) 12%,rgba(242,209,148,.13) 88%,transparent)` -- a 1px rule that fades to transparent at BOTH ends (not a one-sided fade like the --grad-rule pattern the brief describes).
