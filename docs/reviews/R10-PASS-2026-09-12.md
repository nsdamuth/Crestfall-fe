**Risk flagged for G3, not a code change here:** `KitDropdown` is a
filter-bar control: `label` is a persistent prefix, `selectedValues` is
an array, `onToggleOption` is a per-click toggle, and the trigger renders
"label: value" in one control (no separate `<label>` above it). Every one
of the 47 native selects is a single-select form field styled with its
own `FieldLabel`/`SectionLabel` above it. Converting them keeps the same
handler contract (`onChange(value)` still fires with the same string) by
wiring `isMultiSelect={false}`, `selectedValues={[value]}`,
`onToggleOption={(v) => onChange(v)}`, and keeping the field's own label
row instead of `KitDropdown`'s own `label` prop grammar (passing `label=""`
or omitting it and keeping the existing `FieldLabel` above the control).
This is a presentation-only wiring choice under SOP section 13 (same
handler, same reported value), not a contract change, but it is real
per-call-site work, not a blind rename.
