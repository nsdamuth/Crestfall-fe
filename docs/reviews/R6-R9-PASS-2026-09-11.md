## Pass 2, R9 (modal header and divider)

Fixed 34 modal divider files (per the inventory's `d.` table) to the
faded-both-ends gold line. Commit `4cbb5953`.

Reference implementation cited: `components/studio/create/npc-registry/modal-shell/ModalShell.view.jsx:32`,
`<div aria-hidden="true" className="h-px bg-[image:var(--line-fade)]" />`,
the correctly-placed header-to-body divider using the shared
`--line-fade` token (`docs/DESIGN-TOKENS.md:483`:
`linear-gradient(90deg,transparent,rgba(242,209,148,.13) 12%,rgba(242,209,148,.13) 88%,transparent)`,
a gold-tinted line fading to transparent at both ends). Same token and
recipe as the shared `FadeDivider` primitive in
`components/kit/modal-frame/KitModalFrame.view.jsx:70`, and already
used correctly, untouched by this pass, in
`components/kit/save-ingredient-preset/KitSaveIngredientPreset.view.jsx`
and `components/kit/credits/KitCreditsModal.view.jsx`.

31 files received a direct edit, 49 individual divider instances in
total:

- 13 files (26 instances) misapplied `--line-fade` as a `border-color`
  (`border-b border-[var(--line-fade)]` / `border-t
  border-[var(--line-fade)]`), which is invalid CSS for that property
  and renders as a plain currentcolor rule, not a fade. Fixed by
  dropping the border utility and adding the dedicated
  `bg-[image:var(--line-fade)]` hairline `<div>` in its place.
- 9 files (10 instances) carried a literal `border-white/10` (or
  `border-b border-white/10` on the header container itself). Same
  fix: dropped the white border utility, added the hairline `<div>`.
- 6 files (10 instances) used `border-[var(--line-whisper)]`, a flat,
  uniform-opacity solid gold hairline with no fade shape. Same fix.
- 3 files got a divider added where none existed before: the shared
  NPC Registry `ModalActions.view.jsx` footer button row (no divider
  of any kind), `CrestfallOptionModal.view.jsx` (header followed by a
  plain margin-top gap), and `KitPickerModal.view.jsx` (its one
  existing divider sits between the item list and the footer, not
  between the header and body, so a new header-to-body divider was
  added and its existing, already-compliant body-to-footer divider was
  left untouched).

No modal width, height, header copy, native select, or any other R8
or R10 concern was touched; only the divider element or the classes
that render it changed.

3 rows were logged rather than changed:

- `components/studio/creations/buildModalCreationFromPreviewGraph.jsx`:
  not a rendered modal. The whole file is a plain object-merging helper
  function with no JSX at all, so R9 does not apply to it.
- `components/studio/creations/creation-preview-modal/CreationPreviewModal.view.jsx`:
  no header/body seam exists to divide. The modal is a two-column
  image/info layout with only an absolutely-positioned close button;
  there is no title/header block separated from a body, and building
  one to hang a divider on would be a layout restructure, out of scope
  for a divider-only fix.
- `components/ui/modal-shell/ModalShell.view.jsx`: the shared Tier-0
  veil-plus-dialog primitive. It renders only `{children}` with no
  header/body split at this layer; any divider belongs in the specific
  callers that build their own header out of `children`, not in this
  generic base.

Post-fix grep of `border-[var(--line-fade)]` (as a border-color) and
`border-b/border-t border-white/10`/`border-[var(--line-whisper)]`
inside the 34 flagged files confirms zero remain. (Several other,
non-modal files still carry `border-[var(--line-fade)]` misuse, for
example `StoryRoomStatusSurfaceHost.view.jsx`; those are not modals,
were never in the inventory's 58-modal survey, and are out of scope
for this pass.) `npm run build` exits 0.
